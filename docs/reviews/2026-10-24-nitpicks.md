# Nitpick pass: romanica-resourcepack (2026-10-24)

> Owner-requested sweep for every small thing, on top of the 2026-10-23/24 reviews in this folder. Nothing here repeats those docs unless it's still live. Checks were scripted greps and live `curl`s run on 2026-10-24. Each item names the file:line or URL that shows it. Only the items marked as checked live were run against production.

## Findings

Reviewed `main` @ 7ef9ed6 plus the `textures` release assets.
- **Every Java player's pack menu shows "ImperiumMC Texture Pack v2.0.7".** That's the `pack.mcmeta` description inside the v2.0.8 zip the server pushes. It's both the wrong brand and the wrong version, on the most visible string the pack has.
- **The server pushes Bedrock v1 while v2 exists.** The `textures` release has `ImperiumMC_Bedrock_v2.zip` (62 MB, 131 downloads), but the plugin's `config.yml:1012` still points Bedrock players at `ImperiumMC_Bedrock_v1.zip`. Either v2 was never switched on or it was rejected. Record which, and remove the unused one from the release.
- The `textures` tag is mutable ("all packs") and holds the v2.0.7 and v2.0.8 BASE zips side by side. The plugin pins its SHA1 at runtime by URL, so a re-upload under the same name silently changes what players get. Cut immutable `v2.0.8`-style tags.
- Every asset name starts with `ImperiumMC_` and the release is titled "ImperiumMC Textures (all packs)". Rename both in the next release (packs repo issue #1).
- `README.md` is titled "ImperiumMC Resource Pack" and says packs aren't committed to the tree, but six zips are (pass-1 review). README and repo still contradict each other.
- Junk shipped inside `resourcepack.zip`: `pack.credits.txt`, `assets/minecraft/.packsmc/conversion_id`, and `assets/minecraft/font/old font/default.png` (a directory name with a space, unreferenced). It's still in v2.0.8.
- `min_format: [3, 0]` / `max_format: [999, 0]` are still the dishonest range (pass 1). With 26.3 at format 97, `999` is what makes BASE load on 26.3, so set it to the real tested ceiling, not 999.
- `clouds.png` at the repo root is still tracked.
- Housekeeping on the owner's PC: there's a second, stale local clone at `Documents/imperiummc-resourcepack` (last commit 679b9a6, remote set to the pre-rename `Imperium-MC/` URL). It's easy to commit to the wrong copy. Delete it or re-point it.

## Cross-repo inconsistencies

- **Two vote-site lists.** The website has 9 sites (`romanica-frontend/src/lib/site.ts:26-34`); the plugin has 8 plus 34 (`vote-sites.yml`), and most of the 34 are placeholders. Keep one list, in the backend or the plugin config, and have the other read it.
- **Game version.** The plugin `api-version` is 26.2, and the pack and plugin config say `26.2`. The launcher and client ship 26.3, and the website FAQ meta says "1.8–26.2". Settle one statement of "server runs X, client Y, joinable from Z" and use it everywhere.
- **Social handles** are `@PlayImperiumMC` / `r/ImperiumMC` on the website (`site.ts:11-17`, `llms.txt:147-149`). This is the owner's call: rename the accounts, or keep them and note it.
- **"ImperiumMC" in player-visible strings:** Discord changelog footers (backend), the pack menu description (pack), mod-menu source/issue links (client), and launcher support links. Each is listed in its repo's doc.
- **Protocol-locked old names that must NOT be renamed one-sided:** Redis keys `ImperiumMC:*`, permission nodes `imperiummc.*`, mod id and channels `imperiumclient:*`, env var `IMPERIUMMC_HMAC_SECRET`. Rename them only in a coordinated change across both sides.
